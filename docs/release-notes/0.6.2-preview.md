**Follow Claude Code now works, and a full round of fixes.**

This release comes out of a complete audit of the app and a real-life test pass. The main finding: since 0.5.4, *Follow Claude Code* never received a single event.

## What's fixed

- **Follow Claude Code works.** The hook entries written to `~/.claude/settings.json` pointed at a path containing a space, so Claude Code could never run them: no hand, no check, and a hook error in every Claude Code session. The entries are fixed, and the ones already written are replaced once, at the first launch of this version, if the setting is on.
- **No more "limit reached" right after a reset.** When every limit was at 0 or 1 %, the app read 1 % as 100 %: red gauge and a notification at the start of the week.
- **One notification per period, really.** A reached limit or an imminent block could notify again at every reading.
- **Pauses are respected from the start.** Launched in Low Power Mode, or restarted while the screen was locked, the app kept polling.
- **Signing out no longer breaks Follow Claude Code.** It deleted the hook script along with your data.
- **Typing is not swallowed any more.** With the pointer resting on the notch, the open panel took the keyboard and what you typed in your app was lost. The panel now takes the keyboard only when you click inside it or open it on purpose.
- **Settings on a Mac without a notch.** *Settings* from the menu bar icon opened the limits instead.
- **"Plan not supported" recovers on its own.** The app used to stop reading until relaunched; it now retries every hour, and *Refresh now* retries at once.
- **A reached weekly limit reads in days.** `↻3d 5h` instead of `↻77:00`; with two limits reached, the one that comes back last is shown.
- **"Reconnect required" says why.** When macOS only asks again before the app can read the Claude Code session, the panel offers **Allow access** and sends nothing to Claude. **Renew session**, which costs a small request, is kept for a session that has really expired.
- **Refresh interval slider.** Dragging it could send several requests in a row.

## What's new

- **Pending sessions survive a restart.** A Claude Code session waiting for you is still shown after the app restarts or updates.
- **Clear finished sessions from any display.** Click the capsule, or close the menu bar popover: the check goes away, as it does with a click on the island.
- **Open the panel without the pointer.** Open Notch Usage again (Spotlight, Finder): the panel opens with keyboard focus. If the menu bar icon was set to *Never* and nothing shows, this also brings the icon back.
- **One instance only.** A second copy quits and shows the panel of the one already running.
- **Leftover hooks are harmless.** If the app is removed without turning *Follow Claude Code* off, its entries do nothing.

## Privacy and security

- **Redirects stay on Anthropic's hosts.** A redirect to another host is no longer followed, so your token or session cookie cannot be sent elsewhere.
- **Local files.** The sessions being followed are saved in `claude-sessions.json` (session id, working folder, title, tool: never any conversation text), removed when nothing is followed. The events file is capped at 1 MB while the app is closed. The unused `alerts.json` is deleted.
- **Reporting a vulnerability.** See [SECURITY.md](https://github.com/florentmaille/Notch-Usage/blob/main/SECURITY.md).

## Updating

From 0.5.8 or later, use **Settings → Check for updates**. From an older version:

```bash
brew update && brew upgrade --cask notch-usage
```

## Install (preview build, not notarized)

With Homebrew:

```bash
brew install --cask florentmaille/tap/notch-usage
```

Already installed? `brew update && brew upgrade --cask notch-usage`. Otherwise:

1. Download `NotchUsage-0.6.2-preview.zip` below and unzip it.
2. Move **NotchUsage.app** to your Applications folder, replacing the previous version if you have one.
3. Open it. macOS says it cannot verify the developer: click **Done**.
4. Open **System Settings → Privacy & Security**, scroll down and click **Open Anyway** next to Notch Usage, then confirm.

Upgrading: macOS asks again for Keychain access. Click **Always Allow**.

## Known limitations

- Escape closes a panel opened by hovering only after a click inside it; moving the pointer away still closes it.
- The capsule needs a visible menu bar: with *Automatically hide and show the menu bar*, it does not show.
- On displays narrower than 1700 pt, the capsule is not shown, so it never covers app menus; the menu bar icon covers those displays.
- Not notarized: the Keychain may ask again after you replace the app with a newer build. Signed releases will fix this.
- Uses undocumented Anthropic endpoints that may change at any time. Read the [risk note](https://github.com/florentmaille/Notch-Usage#%EF%B8%8F-risk-note-please-read).

Requires macOS 14 (Sonoma) or later, Apple Silicon or Intel.
