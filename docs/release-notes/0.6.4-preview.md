**No conversation text left on disk while the app is closed, and a sturdier Follow Claude Code.**

A small release after 0.6.3: the findings of a new audit of the app, mostly around *Follow Claude Code*.

## Privacy and security

- **Nothing is written while the app is closed.** The hooks stay installed after you quit, and the hook script kept appending each event to `claude-events.jsonl`, up to 1 MB, until the next launch. An event carries your prompt and the tool inputs. The script now writes nothing when the app is not running, and the app empties the file when it stops reading. In return, an event fired while the app is closed is not caught up: a session that starts waiting during that time shows at its next event. Sessions already followed still survive a restart.
- **Cache files are private.** `snapshot.json`, `history.json` and `weekly.json` are written with mode 600, like the other files of the folder.

## What's fixed

- **A blocked request no longer asks you to sign in again.** Behind some networks (VPN, firewall), claude.ai answers with a block page. The app took it for an expired session and stopped reading. It now shows the browser-check banner and retries on its own.
- **Menu bar and capsule: the reset arrow of a reached limit.** They now show `↻` and the time left, like the island.
- **No ghost approval.** A Claude Code session killed without a clean end could stay shown as waiting until the Mac restarted, when macOS gave its process number to another process. Such a session is now dropped.
- **Follow Claude Code recovers from a deleted events file.** If the file was removed or replaced, no event arrived until the app restarted. The app now reopens it, and *Repair* restarts the reading.
- **No event lost under load.** A hook writing at the very moment the app emptied the file could lose its event.
- **Renew session with Claude Code installed by npm or bun.** The renewal could fail because Claude Code did not find `node` or `bun`.

## Updating

From 0.5.8 or later, use **Settings → Check for updates**. From an older version:

```bash
brew update && brew upgrade --cask notch-usage
```

The hook script is rewritten at the first launch of this version, if *Follow Claude Code* is on.

## Install (preview build, not notarized)

With Homebrew:

```bash
brew install --cask florentmaille/tap/notch-usage
```

Already installed? `brew update && brew upgrade --cask notch-usage`. Otherwise:

1. Download `NotchUsage-0.6.4-preview.zip` below and unzip it.
2. Move **NotchUsage.app** to your Applications folder, replacing the previous version if you have one.
3. Open it. macOS says it cannot verify the developer: click **Done**.
4. Open **System Settings → Privacy & Security**, scroll down and click **Open Anyway** next to Notch Usage, then confirm.

Upgrading: macOS asks again for Keychain access. Click **Always Allow**.

## Known limitations

- Escape closes a panel opened by hovering only after a click inside it; moving the pointer away still closes it.
- The capsule needs a visible menu bar: with *Automatically hide and show the menu bar*, it does not show.
- On displays narrower than 1700 pt, the capsule is not shown, so it never covers app menus; the menu bar icon covers those displays.
- Not notarized: the Keychain may ask again after you replace the app with a newer build. Signed releases will fix this.
- Uses undocumented Anthropic endpoints that may change at any time. Read the [risk note](https://github.com/florentmaille/Notch-Usage#%EF%B8%8F-risk-note-please-read).

Requires macOS 14 (Sonoma) or later, Apple Silicon or Intel.
